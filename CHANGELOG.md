## [v1.0.39] - 2026-10-22
### 🧠 Custom Discord Chat AI Model (Ping Responses)
- **Lightweight Hybrid Conversational + Markov AI Model**:
  - Trained on 409,835 Discord messages and 347,753 conversational pairs directly on the server (`discord_ai_model.json`, 16 MB).
  - Combines BM25/IDF contextual dialog retrieval (`40,000` indexed conversational pairs across `18,465` vocabulary terms) with a keyword-seeded Trigram/Bigram Markov language model (`106,000` trigram states and `24,246` bigram states).
- **Pingable AI Responses**:
  - Mentioning/pinging the bot (or replying to the bot with ping enabled) now generates contextual responses using the trained model while preserving `@Bot <command>` support for actual bot commands.

## [v1.0.36] - 2026-10-19
### ⚙️ Enhanced Parameter Parsing for Prefix Commands
- **Named Parameter Support**:
  - Added support for named parameters in prefix commands (`!cb pay user:@Logan amount:50`, `!cb pay user=@Logan amount=50`, `!cb pay --user @Logan --amount 50`).
  - Supports colon, equals, and flag syntax (`param:val`, `param=val`, `--param val`, `--param=val`, `-param val`).
  - Correctly preserves internal colons (e.g. `event_url:https://ofratings.com/events/10`).
  - Normalizes parameter keys with kebab-case and snake_case (`start-date`, `start_date`, `startdate`).
- **Quotes & Flag Handling**:
  - Properly unquotes values in double quotes, single quotes, or inline quoted arguments (e.g. `name:"Fall Championship"`, `name:'Tournament'`).
  - Handled standalone boolean flags (e.g. `!cb link-ratings --clear` or `!cb event --require_join`).
- **Positional & Mixed Mode Compatibility**:
  - Maintained full backwards-compatibility with positional arguments (e.g. `!cb pay @Logan 50`).
  - Supports mixed positional and named arguments with remaining unassigned parameters mapped in order.

## [v1.0.33] - 2026-10-19
### ⚙️ Configurable Anti-Cheat: Minimum Tiles, Survival Time & Troop Attack Thresholds
- **Customizable Anti-Cheat Requirements**:
  - Added configurable anti-cheat parameters to `TournamentConfig`:
    - `minTiles`: Minimum peak tiles required before defeat qualifies (default: 100 tiles; initial spawn gives ~52 tiles).
    - `minSurvivalSeconds`: Minimum match survival time required before defeat qualifies (default: 60 seconds).
    - `minAttacks`: Minimum offensive attack troops sent (default: 1 troop).
  - Matches where the player achieved territory conquests or player kills are recognized as direct combat proof and always qualify.
- **Settings Dashboard Integration (`/config`)**:
  - Added dedicated **`🛡️ Anti-Cheat`** interactive button in Row 4 of the main `/config` settings dashboard.
  - Added dedicated interactive modal `cfg_modal_anticheat` allowing server administrators to customize minimum peak tiles, minimum survival time, and minimum attack troops directly.
  - Integrated 5th input into the existing `🏆 Tourney Scoring` modal (`cfg_modal_tourney`) allowing dual configuration from both entrypoints.
  - Main settings overview embed now clearly displays active anti-cheat thresholds under `🏆 Tournament Scoring & Anti-Cheat`.
- **Match Telemetry & Leaderboard Enhancements**:
  - Refactored `verifyGameParticipation` to cache full match telemetry (`PlayerMatchTelemetry`) per `gameId:publicId`, ensuring instantaneous re-evaluation when threshold settings are updated.
  - Fixed duplicate increment of `gamesPlayed` count on valid games and ensured disqualified matches do not count towards `gamesPlayed`.
  - Updated live leaderboard scoring rules description to display active minimum tiles and survival seconds.

## [v1.0.32] - 2026-10-19
### 🛡️ Competition Anti-Cheat: Active Gameplay & Anti-AFK Verification
- **Anti-AFK & Zero-Action Game Disqualification**:
  - Implemented `verifyGameParticipation()` in `OpenFrontApi` to inspect game telemetry and player statistics.
  - Automatically detects and disqualifies defeat games where a player joined a lobby but took no gameplay actions (e.g., joining an 80+ player game, never spawning or remaining idle, and collecting participation points).
  - Matches where a player sent 0 attack troops, conquered 0 tiles, achieved 0 kills, and never expanded beyond starting territory (<= 52 tiles) or died in early ticks without attacking are disqualified from awarding tournament points and counting towards games played.
  - Legitimate defeats where players actively attacked, expanded, conquered territory, or fought are preserved and scored normally.
- **In-Memory Anti-Cheat Caching**:
  - Added `gameParticipationCache` to cache verified game participation results by `gameId:publicId`, ensuring zero redundant network fetches during rapid leaderboard refreshes.
- **Leaderboard Telemetry Update**:
  - Updated `/competition` and `/leaderboard` rules description to clearly state: `Active gameplay required (AFK/0-attack excluded)`.
